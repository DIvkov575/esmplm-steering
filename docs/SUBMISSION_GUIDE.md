## Why the structures differ

The arXiv and Interp4Discovery manuscripts follow a conventional research
paper order: Introduction, Related Work, Methods, Results, Failure
Analysis, Discussion, Limitations, and Conclusion.

ICBINB-BIO requires failure reports to contain four elements: Problem,
Proposed Approach, Observed Outcome, and Reason for Failure. The official
sources do not explicitly require those names as literal headings. We use
them as headings so reviewers can locate each required element. They are not
an unconventional appendix.

The disclosure, code-availability, reproducibility, and responsible-use
sections are end matter. They are also not appendices. If a real appendix
is added later, it should begin with `\appendix` after the references, or
be uploaded as a separate supplement if the venue requires that format.

The line beginning with "Submitted to" at the bottom of the first page is
generated by `neurips_2026.sty`. It is a normal submission footer from the
official workshop template and should remain in the review PDF.

## Later preprints and anonymous review

Both workshop policies permit preprints, but a public version with the same
title and text can reveal the author of a double-blind submission. The current
program therefore does not prepare or post a named preprint. Any later release
starts only after the workshop submission work is complete.

## Code during review

The current drafts do not require an anonymous GitHub repository. If
reviewers need code, use this order:

1. Upload an anonymous source archive through the submission system.
2. Use an anonymous repository snapshot only if external links are
   permitted and the archive is too large.
3. Release the named GitHub repository after double-blind review.

Do not link the existing public repository from an anonymous manuscript.
Its URL and history identify the author. Before uploading any supplement,
search both the files and PDF for:

```text
Ivkov
divkov
DIvkov575
umich
University of Michigan
github.com
```

Also remove Git metadata, remote URLs, local absolute paths,
acknowledgments, and PDF author metadata.
